资源配额 (ResourceQuota)

-- namespace: oa-prod 的资源配额 apiVersion: v1 kind: ResourceQuota metadata: name: oa-prod-quota namespace: oa-prod spec: hard: requests.cpu: "40" # 总 CPU 请求上限 requests.memory: 80Gi # 总内存请求上限 limits.cpu: "60" limits.memory: 120Gi pods: "50" # 最大 Pod 数 persistentvolumeclaims: "10"
每个微服务 Deployment 配置 requests: 500m/1Gi、limits: 2000m/4Gi，保证节点资源利用率 70% 以下时仍有余量。

5. CI/CD 流水线

.gitlab-ci.yml 关键阶段

# .gitlab-ci.yml — OA 系统 CI/CD 流水线定义 stages: - lint - build - test - push - deploy-staging - approval - deploy-prod # 阶段1: 代码检查 lint: stage: lint image: node:20-alpine script: - npm ci - npm run lint - echo "Lint passed" rules: - if: $CI_PIPELINE_SOURCE == "merge_request_event" # 阶段2: 构建 build: stage: build image: maven:3.9-eclipse-temurin-21 script: - mvn clean package -DskipTests - docker build -t $HARBOR_URL/oa-workflow:$CI_COMMIT_SHORT_SHA . artifacts: paths: - target/*.jar # 阶段3: 测试 (单元 + 质量 + 安全) test: stage: test script: - mvn test # 单元测试，覆盖率 ≥80% - sonar-scanner # SonarQube 代码质量 - trivy image --exit-code 1 $HARBOR_URL/oa-workflow:$CI_COMMIT_SHORT_SHA coverage: '/Total.*?(\d+\.\d+)%/' # 阶段4: 推送镜像到 Harbor push: stage: push script: - docker push $HARBOR_URL/oa-workflow:$CI_COMMIT_SHORT_SHA - docker tag $HARBOR_URL/oa-workflow:$CI_COMMIT_SHORT_SHA $HARBOR_URL/oa-workflow:latest - docker push $HARBOR_URL/oa-workflow:latest rules: - if: $CI_COMMIT_BRANCH == "main" # 阶段5: 自动部署到 Staging deploy-staging: stage: deploy-staging script: - argocd app sync oa-staging --prune - argocd app wait oa-staging --timeout 300 environment: name: staging # 阶段6: 生产部署审批门禁 approval: stage: approval script: - echo "等待人工审批..." when: manual # 需手动点击通过 allow_failure: false # 阶段7: 滚动部署到生产 deploy-prod: stage: deploy-prod script: - argocd app sync oa-prod --prune - argocd app wait oa-prod --timeout 600 environment: name: production rules: - if: $CI_COMMIT_BRANCH == "main"

部署策略

环境策略说明
StagingRolling Update滚动更新，maxUnavailable=1, maxSurge=1
ProductionCanary → FullArgoCD + Istio：先切 10% 流量灰度 10 分钟，健康指标正常后全量
RollbackArgoCD Rollback一键回滚至上一 Revision，argocd app rollback oa-prod

6. 监控与可观测性

核心监控指标

分类指标告警阈值说明
基础设施Node CPU 使用率>85% 持续 5minPrometheus node_exporter
基础设施Node 内存使用率>90% 持续 5min触发 Pod 驱逐前预警
容器Pod 重启次数>3 次/10minCrashLoopBackOff 预警
应用API P99 延迟>500ms 持续 5minIstio 指标
应用HTTP 5xx 错误率>1% 持续 2min触发自动回滚
业务流程实例积压>100 待办未处理定时巡检 + 业务大盘
业务任务超时未签收超 due_at 30min提醒审批人 + 上级
数据库MySQL 慢查询>1s 持续 3minpt-query-digest
Grafana 看板规划：
• 集群总览 — 节点资源、Pod 状态、HPA 扩缩事件
• 微服务健康 — QPS / 延迟 / 错误率 / 熔断次数（按服务分页）
• 业务运营 — 流程发起量 / 待办积压 / 超时率 / 审批平均耗时
• 数据库 — 连接池 / QPS / 慢查询 / 主从延迟
• 告警大屏 — 实时告警列表 + 值班轮换
