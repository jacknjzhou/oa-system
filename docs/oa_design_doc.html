1. 整体架构

系统采用五层分层架构，从接入层到基础设施层，各层职责清晰、解耦分明。

架构分层说明

接入层 — 统一多端入口：Web SPA、移动 App、企微/钉钉第三方接入，三端共用同一套 API。

网关层 — API 网关（架构焦点）：统一鉴权（JWT/OAuth2）、路由分发、限流熔断、请求日志。

应用服务层 — 6 大微服务：用户与组织、工作流引擎（核心）、公文管理、审批管理、日程与任务、消息通知。

数据存储层 — 混合存储：MySQL（业务数据）、Redis（缓存/会话）、对象存储（文件）、ElasticSearch（全文检索）。

基础设施 — 横切关注点：消息队列、日志监控、配置中心、CI/CD。

决策点方案理由
服务拆分按业务域垂直拆分工作流、公文、审批各自独立演进
工作流引擎集成 Flowable/ActivitiOA 核心能力，需灵活定制审批流
通信方式同步 REST + 异步消息公文流转同步，通知推送异步
多端适配API 网关统一入口避免各端各自实现鉴权逻辑

2. 工作流引擎设计

流程定义模型

概念说明关键字段
流程定义 ProcessDefinition审批流程的模板蓝图id, name, version, status, node_json
流程实例 ProcessInstance一次具体的审批申请id, def_id, initiator_id, status, business_data
节点 Node流程中的审批/分支环节id, def_id, type, name, assignee_type
连线 Transition节点间的流转路径id, from_node, to_node, condition_expr

5 种节点类型

类型图示说明
开始节点胶囊形标记流程入口，自动创建第一个任务
审批节点矩形 (brand)支持单人审批、多人会签、或签三种模式
条件节点菱形基于表达式（如金额阈值）做分支路由
并行节点矩形 (accent)同时分发给多人，全部完成才汇聚
结束节点胶囊形标记流程完结，触发归档/通知

流转规则

规则说明
顺序流转默认路径，上一节点完成自动激活下一节点
条件分支菱形节点求值 condition_expr，匹配的出口连线激活
并行汇聚会签节点所有审批人完成后，汇聚到下一节点
驳回退回虚线箭头，可退回到任意前序节点
加签/转办审批中动态追加审批人或转交他人，不改变流程拓扑

4. API 接口设计

采用标准 RESTful 规范，按业务域分组，共 17 个核心接口。

RESTful 约定：资源命名用复数名词 · 嵌套路由 /api/{parent}/{id}/{child} · 非 CRUD 动作用 /{action} 后缀 · 统一响应 { code, message, data } · 分页 ?page=1&size=20

用户认证

MethodPath说明
POST/api/auth/login登录，返回 JWT
POST/api/auth/logout登出，失效 Token
GET/api/auth/profile当前用户信息
GET/api/users用户列表（分页）
GET/api/organizations组织架构树

流程管理

MethodPath说明
GET/api/process-definitions流程定义列表
POST/api/process-definitions创建流程定义
POST/api/process-instances发起流程实例
GET/api/process-instances/{id}流程实例详情
POST/api/process-instances/{id}/cancel撤销流程

任务管理

MethodPath说明
GET/api/tasks当前用户待办列表
GET/api/tasks/{id}任务详情（含审批表单）
POST/api/tasks/{id}/complete完成审批（通过）
POST/api/tasks/{id}/reject驳回至指定节点
POST/api/tasks/{id}/transfer转办给他人

公文管理

MethodPath说明
POST/api/documents创建公文
GET/api/documents公文列表（分页）
GET/api/documents/{id}公文详情
PUT/api/documents/{id}更新公文内容
POST/api/documents/{id}/archive归档公文

状态码约定：200 成功 · 201 创建 · 400 参数错误 · 401 未认证 · 403 无权限 · 404 不存在 · 500 服务器错误

5. 审批流转状态机

流程实例状态

状态说明流转触发
草稿 DRAFT发起人编辑中，未提交提交 → 进行中
进行中 RUNNING流程已启动，节点流转中全通过 → 已完成 · 撤回 → 已撤销
已完成 COMPLETED所有节点通过，流程归档终态
已撤销 CANCELLED发起人主动撤销终态

任务状态

状态说明流转触发
待处理 PENDING任务已生成，等待签收签收 → 处理中
处理中 PROCESSING审批人已接手通过 → 已通过 · 驳回 → 已驳回 · 转办 → 已转办
已通过 APPROVED审批同意，激活下一节点终态
已驳回 REJECTED审批不同意，退回指定节点终态（可触发新任务）
已转办 TRANSFERRED转交他人处理，生成新任务终态（触发新待办）
设计要点：驳回不终止流程——退回到指定节点后重新生成待处理任务。转办不改流程拓扑，仅替换 assignee 并记录审批留痕。撤销仅发起人可操作，且仅在流程未完成时可用。
